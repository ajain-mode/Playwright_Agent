Testmo Export Repository — Critical Automation Blocker Analysis

What in the Testmo test case export prevents reliable Playwright spec generation via the agent pipeline — and what to fix first.

This review compares the Testmo export backlog (1,125 cases) to the gold standard: 28 executable test cases the agent has already completed, catalogued in sample-testcases.csv. Those 28 define the step detail, test data, and Expected results needed for dependable generation.

What we analysed: whether each Testmo case is agent-ready (procedure depth, login/navigation language, fixtures, role/cross-app handoff, Expected clarity, and View Load vs View Billing wording).
How: converted the export to the same columns as sample-testcases.csv; scored all 1,125 cases against the gold standard in sample-testcases.csv; detected extractable values that the agent would push into category CSVs (billingtoggledata.csv, dfbdata.csv, … via FieldRegistry); grouped blockers into four clearly defined, volume-ranked issues; and measured closeness to gold-standard procedure depth.

Missing CSV-bound test data (category data files) 1 · Largest volume · 799 of 1,125 cases (71.0%)

Definition: The agent parses concrete values from Precondition / Test Steps / Expected (via FieldRegistry) and writes them into runtime category CSVs such as billingtoggledata.csv and dfbdata.csv (columns like officeName, customerName, shipperName, consigneeName, equipmentType, loadMethod, qty/weight, offerRate/linehaulRate, zips, Carrier, loadId). This issue flags cases that need that runtime testData (create load, rates, customer/office search, EDI, etc.) but do not supply enough extractable field values (fewer than 3 CSV field families), or cite EDI/Postman/Sterling with no payload values.

Without those values the pipeline cannot fill testData.* / category CSV rows, so generated specs guess or skip data setup. Largest backlog issue under this CSV-aligned definition (~925 cases imply needing category CSV data; only ~145 have ≥3 extractable field families).

Fix: Author Field:Value (or explicit “enter X as Y”) for every CSV-bound field the flow needs — same density as gold-standard cases in sample-testcases.csv.
Clubs: Missing test data / fixtures · External EDI / Postman / Sterling without payload

Incomplete test procedures (not automation-ready) 2 · Next largest volume · 744 of 1,125 cases (66.1%)

Definition: Steps are too short (<200 characters), unnumbered, start UI actions without login/sign-in, or use “navigate to…” without hover→submenu language the agent maps to hoverOverHeaderByText / submenu clicks. This is about how the case is written, not about category CSV columns.

The agent cannot assemble a reliable Playwright path from summary or observe-only steps. Second-largest issue. Often overlaps with missing CSV data.

Fix: Gold-standard shape: login → hover menu → click submenu → enter named fields — one action per step.
Clubs: Thin / non-atomic procedure · Missing login / session · Weak BTMS navigation language

Missing role switch & cross-application handoff 3 · Next volume band · 410 of 1,125 cases (36.4%)

Definition: Case requires a specific role / Switch User / Switch Account, but does not name the user (or USER_ROLES-style constant) to select; and/or jumps to DME, TNX, or carrier portal without capturing a Load ID (or equivalent search key) for the next app. Distinct from category CSV field values — this is session identity and multi-app continuity.

Specs cannot switch account or find the load in DME/TNX without guessing. Third band by volume.

Fix: Name the user + Switch Account steps; after create, record Load ID; document each app switch + search.
Clubs: Role / switch-user undefined · Cross-app without load ID / handoff

Unclear Expected results & ambiguous screens 4 · Remaining volume band · 248 of 1,125 cases (22.0%)

Definition: Expected is soft (“accordingly”, “seems disabled”); or Waiting On / NDF / billing toggle is discussed without naming View Load (Load tab) vs View Billing (different POMs / fields). This is about assertable outcomes and screen identity — not category CSV columns.

Agent cannot place hard expects or picks the wrong page object for Waiting On / finance tags. Fourth band by volume.

Fix: Expected = control + value (Ensure after Step N). Name View Load vs View Billing.
Clubs: Soft / unverifiable Expected · View Load vs View Billing ambiguity
