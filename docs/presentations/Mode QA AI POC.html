Agent Architecture Workflow — What the Pipeline Does at Each Level

The QA AI Agent turns detailed written test cases (from Testmo, CSV, Excel, or plain text) into runnable Playwright scripts. It uses a hybrid approach: proven automation patterns and real UI locators from application source code first; Claude AI only where rules alone cannot complete the job. Every script passes through automated quality checks before it is saved — nothing is silently dropped.

Level 0 · Input

Written Test Cases

QA provides test cases with full step-by-step actions and expected results. The pipeline accepts CSV, Excel, JSON, or plain text. The richer the testcase, the more accurate the generated script.

  • Runtime test data (customer, office, rates, etc.) loaded from per-category CSV files
  • Canonical step catalog maintained in sample-testcases.csv for traceability
Level 1 · Preparation

Get Context Before Writing Code

Before any script is generated, three preparation steps ensure the agents work from facts — not guesses.

Test Case Reader
Reads and parses the testcase — extracts steps, expected results, category, and test data fields.
App Context Sync
Clones the latest BTMS and DME application source repos so locators reflect the real product UI.
UI Element Index
Indexes 5,900+ HTML element IDs from application source — locators are never fabricated.
Data Enricher (AI Call 1)
Claude fills in missing test data fields that could not be parsed from the written testcase.
Level 2 · Script Assembly

Build the Draft Playwright Script

The Script Assembler turns understood steps into executable code. Rules and patterns are tried first; AI is used when no pattern matches or when adapting a similar reference test.

① Step Interpreter
Understands what each step means — which screen, which tab, edit vs view mode, and which application (BTMS, DME, or TNX). Passes structured context to the next agent.
② Code Mapper
Maps steps to proven automation actions using 130+ patterns and indexed UI locators. Reuses page object methods from the existing Playwright framework. Can propose new methods when needed.
✦ AI Script Writer (Calls 2–4)
Claude writes or adapts code when rules cannot resolve a step: full script from a reference template, smart adaptation of a similar test, or per-step code as a last resort.
Draft Script
Output of this level: an assembled .spec.ts file ready for validation — not yet saved.
Level 3 · Quality Validation

③ Quality Guardian — Validate & Self-Heal

Every draft script is checked against 25+ quality rules and guardrails before QA ever sees it. Common issues are auto-fixed — for example wrong navigation order, hardcoded values, missing user switches, or locators written directly in the spec.

  • Receives the draft script plus step context from the Step Interpreter and Code Mapper
  • Runs up to 2 correction passes — sends fixes back to the Code Mapper when violations are found
  • Enforces Cursor governance rules: protect human-authored page objects, use constants, scoped report grid locators
Level 4 · Coverage Check

④ Coverage Ensurer — Nothing Silently Dropped

Compares the validated script against the original testcase step-by-step. If any written step or expected result is missing from the code, the agent injects it or flags it for human review.

  • One pass — fills up to 8 missing steps per script
  • If changes are made, re-runs the Quality Guardian once before saving
  • Ensures every explicit expected result from Testmo has a matching assertion in the script
Level 5 · Output

Runnable Playwright Test Script

The finished script is saved to src/tests/AIAgent/<category>/, with parsed test data written to the category CSV. Scripts are traceable to original testcase step numbers, executable in CI, and reportable via Allure and Testmo.

  • 28 POC scripts delivered — 24 billing toggle + 4 DFB
  • QA executes → feedback → agent retrained → next generation improves (the cycle used throughout the POC from March onward)

Agent Reusability — How QA Uses This in Daily Test Execution

Summary: The QA AI Agent is not a one-time POC deliverable — it is a repeatable production tool wired into the same Playwright framework QA already runs. Every new detailed testcase can flow through the same workflow (Steps 0–5) to produce a validated script; every execution cycle makes the next generation better. The 28 POC scripts are the starting regression suite in CI; the agent, CLI, patterns, and governance rules stay in the repo for ongoing use by Mode Global QA after July handover.

Daily QA workflow with the agent

1. Write or export testcase with full steps and expected results
→
2. Run agent CLI to generate or preview the spec
→
3. Review generated script and run locally or in CI
→
4. Check Allure report and Testmo results
→
5. Log feedback; retrain patterns or regenerate

Run existing POC suites (regression)

  • Execute all 28 AI-generated specs already deployed in CI — 24 billing toggle + 4 DFB under src/tests/AIAgent/
  • Run a single spec: npx playwright test src/tests/AIAgent/billingtoggle/BT-74454.spec.ts
  • Full suite with Allure: npm run test:allure then submit to Testmo: npm run submit:testmo

Generate a new script from a testcase

  • Interactive (recommended for first use): npm run agent:cli
  • From CSV / Excel / JSON: npm run agent -- --file path/to/testcase.csv
  • Preview without saving: npm run agent:preview "Login BTMS and verify load status"
  • Batch for a folder: npm run agent:batch ./path/to/testcases/

Prepare testcases the agent can reuse

  • Include numbered steps and explicit expected results — the Coverage Ensurer maps these 1:1 to assertions
  • Add runtime data to the category CSV under src/data/<category>/ or let the agent enrich missing fields
  • Maintain canonical steps in src/agent/examples/sample-testcases.csv for traceability
  • Similar cases adapt faster from reference specs in the same category (billing toggle, DFB, etc.)

Continuous improvement (the POC feedback loop)

  • When a generated script fails or needs a manual fix, document the gap — pattern library and guardrails are updated so the next generation is correct
  • Analyze before generating: npm run agent:analyze "your testcase description"
  • Governance rules in .cursor/rules/ and SpecValidator guardrails keep output consistent with team standards
  • Handover doc docs/handover/QA-AI-Agent-Handover.docx covers setup, env vars, and full CLI reference
Takeaway for Mode Global QA: Use the agent for new automation (generate → review → CI), use the 28 POC specs for ongoing regression, and keep feeding execution feedback into the pipeline so each sprint needs less manual script work than the last.
